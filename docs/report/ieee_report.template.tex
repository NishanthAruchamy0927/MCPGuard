\begin{abstract}
AI agents act on external systems through Model Context Protocol (MCP) tools that they understand only through a name, a description and a JSON input schema. We frame tool-definition risk as supervised learning. We assemble {{N_RAW}} MCP-format tool records ({{N_BFCL}} real BFCL functions with real queries and gold calls, {{N_MCP}} MCP reference-server tools, {{N_AUG}} documented augmentations), labelled by a controlled agent benchmark with BFCL-style call validation. Fused TF-IDF/LSA, MiniLM sentence-embedding, JSON-schema and engineered risk features feed 14 models; XGBoost and LightGBM are tuned with Optuna under grouped cross-validation. The selected {{MODEL}} reaches test PR-AUC {{PR_AUC}} (95\% CI {{PR_CI}}), ROC-AUC {{ROC_AUC}} and F1 {{F1}}, versus {{DUMMY_PR_AUC}} (no-skill) and {{RULE_PR_AUC}} (documentation-quality heuristic). Feature fusion adds {{ABL_GAIN}} PR-AUC over the best single family. SHAP explanations drive actionable recommendations, and the system is deployed with FastAPI and Docker and is publicly available on Hugging Face Spaces.
\end{abstract}

\section{Introduction}
An MCP tool exposes \texttt{name}, \texttt{description} and \texttt{inputSchema} to an agent, which must select the right tool and construct a valid call~\cite{mcp}. Vague, untyped or deeply nested definitions cause routing errors, missing arguments and invalid values. Our objectives are: (i) a provenance-labelled dataset with measured failure labels; (ii) multimodal feature engineering with dimensionality reduction; (iii) a benchmark of baseline and tuned models; (iv) SHAP explanations with recommendations; (v) containerised deployment.

\section{Literature Review}
Toolformer~\cite{toolformer} and ReAct~\cite{react} established tool-augmented LMs. Gorilla and BFCL~\cite{gorilla} evaluate agents with AST matching against gold calls, and ToolLLM~\cite{toolllm} scales tool use to real APIs. Hsieh et al.~\cite{hsieh} and EasyTool~\cite{easytool} show that documentation quality affects agent success, but they treat documentation as an intervention. Within the surveyed literature, we found no work that predicts tool-level failure risk from the definition alone; that is the gap we address.

\section{Methodology}
\textbf{Labels.} For each tool, a documentation-bounded simulated agent runs 10 episodes. Routing uses an embedding softmax over co-loaded sibling and random tools. Argument success probabilities depend on literal values in the request and on what the documentation exposes. Calls are validated against the hidden schema and gold values, and $y=\mathbb{1}[\text{failure rate}\ge 0.30]$. Mean episode failure is {{MEAN_FAIL}}.
\textbf{Features.} TF-IDF word/char n-grams $\rightarrow$ TruncatedSVD (64); all-MiniLM-L6-v2~\cite{sbert} $\rightarrow$ PCA (48); 26 schema and 25 lexical statistics; six bounded risk scores, e.g.\ $\text{ambiguity}=\min(1,\,5v/T+0.5\,\mathbb{1}[T<6])$. Fused dimension: {{N_FEATURES}}.
\textbf{Models.} LR, RF, XGBoost~\cite{xgb}, LightGBM~\cite{lgbm}, HistGB and MLP, with cost-sensitive weights and a validation-tuned threshold. Optuna~\cite{optuna} (TPE + median pruning) maximises grouped-CV average precision ({{OPT_XGB_TRIALS}}/{{OPT_LGB_TRIALS}} trials). The split is stratified and grouped by lineage (70/15/15: {{N_TRAIN}}/{{N_VAL}}/{{N_TEST}}); selection uses validation PR-AUC, then F1, then ROC-AUC.

\section{Conclusion \& Future Scope}
Tool-definition risk is learnable and explainable; representation fusion matters more than the choice of learner. The system runs in a non-root Docker container and is publicly deployed on Hugging Face Spaces at \url{https://nishanth0811-mcpguard.hf.space} (Gradio analyzer at \url{https://nishanth0811-mcpguard.hf.space/gradio}); source code: \url{https://github.com/NishanthAruchamy0927/MCPGuard}. The main limitation is that labels come from a calibrated simulated agent. Future work: relabel with real LLM agents, add closed-loop description rewriting, and train on production telemetry.
