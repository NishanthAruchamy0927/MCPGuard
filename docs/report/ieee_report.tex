\title{Predicting Which MCP Tool Descriptions Cause Agent Errors: An Explainable Machine Learning Framework for Detecting High-Risk Model Context Protocol Tool Descriptions}
\author{\IEEEauthorblockN{Student Name(s)}
\IEEEauthorblockA{Department of Computing -- AI \& ML, Coimbatore Institute of Technology\\19MAM56 Advanced Machine Learning Lab -- CAT II}}
\maketitle

\begin{abstract}
AI agents act on external systems through Model Context Protocol (MCP) tools that they understand only through a name, a description and a JSON input schema. We frame tool-definition risk as supervised learning. We assemble 2181 MCP-format tool records (1579 real BFCL functions with real queries and gold calls, 99 MCP reference-server tools, 503 documented augmentations), labelled by a controlled agent benchmark with BFCL-style call validation. Fused TF-IDF/LSA, MiniLM sentence-embedding, JSON-schema and engineered risk features feed 14 models; XGBoost and LightGBM are tuned with Optuna under grouped cross-validation. The selected XGBoost (Optuna-tuned) reaches test PR-AUC 0.709 (95\% CI [0.624, 0.793]), ROC-AUC 0.779 and F1 0.684, versus 0.406 (no-skill) and 0.416 (documentation-quality heuristic). Feature fusion adds +0.033 PR-AUC over the best single family. SHAP explanations drive actionable recommendations, and the system is deployed with FastAPI and Docker.
\end{abstract}
\begin{IEEEkeywords}Model Context Protocol, function calling, LLM agents, explainable AI, SHAP, XGBoost, Optuna\end{IEEEkeywords}

\section{Introduction}
An MCP tool exposes \texttt{name}, \texttt{description} and \texttt{inputSchema} to an agent, which must select the right tool and construct a valid call~\cite{mcp}. Vague, untyped or deeply nested definitions cause routing errors, missing arguments and invalid values. Our objectives are: (i) a provenance-labelled dataset with measured failure labels; (ii) multimodal feature engineering with dimensionality reduction; (iii) a benchmark of baseline and tuned models; (iv) SHAP explanations with recommendations; (v) containerised deployment.

\section{Literature Review}
Toolformer~\cite{toolformer} and ReAct~\cite{react} established tool-augmented LMs. Gorilla and BFCL~\cite{gorilla} evaluate agents with AST matching against gold calls, and ToolLLM~\cite{toolllm} scales tool use to real APIs. Hsieh et al.~\cite{hsieh} and EasyTool~\cite{easytool} show that documentation quality affects agent success, but they treat documentation as an intervention. Within the surveyed literature, we found no work that predicts tool-level failure risk from the definition alone; that is the gap we address.

\section{Methodology}
\textbf{Labels.} For each tool, a documentation-bounded simulated agent runs 10 episodes. Routing uses an embedding softmax over co-loaded sibling and random tools. Argument success probabilities depend on literal values in the request and on what the documentation exposes. Calls are validated against the hidden schema and gold values, and $y=\mathbb{1}[\text{failure rate}\ge 0.30]$. Mean episode failure is 27.4%.
\textbf{Features.} TF-IDF word/char n-grams $\rightarrow$ TruncatedSVD (64); all-MiniLM-L6-v2~\cite{sbert} $\rightarrow$ PCA (48); 26 schema and 25 lexical statistics; six bounded risk scores, e.g.\ $\text{ambiguity}=\min(1,\,5v/T+0.5\,\mathbb{1}[T<6])$. Fused dimension: 169.
\textbf{Models.} LR, RF, XGBoost~\cite{xgb}, LightGBM~\cite{lgbm}, HistGB and MLP, with cost-sensitive weights and a validation-tuned threshold. Optuna~\cite{optuna} (TPE + median pruning) maximises grouped-CV average precision (40/30 trials). The split is stratified and grouped by lineage (70/15/15: 1537/307/308); selection uses validation PR-AUC, then F1, then ROC-AUC.

\section{Implementation \& Experiments}
Python 3.14, scikit-learn, XGBoost, LightGBM, sentence-transformers, Optuna, SHAP~\cite{shap}, MLflow and FastAPI; seed 42. Dataset: 2152 clean records, 670 servers, positive rate 40.7%. Top SHAP drivers: Schema size, Text theme #23 (distance, untyped, search), Schema complexity score, Text theme #45 (function, coordinates, longitude), Average word length.

\section{Conclusion \& Future Scope}
Tool-definition risk is learnable and explainable; representation fusion matters more than the choice of learner. The main limitation is that labels come from a calibrated simulated agent. Future work: relabel with real LLM agents, add closed-loop description rewriting, and train on production telemetry.
